# Modelling conventions

This repository's settled conventions for the Structurizr model. The `c4` skill reads this file first, and it wins where the two differ.

- **Packages are one container, each package one of its components.** `pipeline.packages` (`Packages`) holds one component per directory under `packages/`, and the DSL is the list, keeping the package layer at the same level as the pipeline-stage containers `model.dsl` declares beside it rather than mixing individual packages in as their siblings. The `PackagesComponents` view shows them individually.
- **The platform is its own client.** A pipeline component calling a package (`orchestration.cleansing -> packages.cleanseRules`) is the same shape as `externalConsumers -> packages.cleanseRules`: the packages are pure and callable standalone, and this repo's orchestration only adds its own data plumbing (`system_uri`, dataframes, parquet I/O) around those calls.
- **Name a package for what it does, not for its data.** `company_cleanse` is the "Company Cleanse Engine" that *applies* rules, not a "Rules Engine" holding them. Relationship descriptions follow suit: the caller *invokes*, the engine does the work.
- **Everything the Data Engineer runs goes through `cli`.** `dataEngineer -> pipeline.cli`, then `cli` fans out to `orchestration`, `training`, `validation`, `blocking`. Don't add person-to-container edges bypassing `cli`.
- **Planned relationships are tagged, not commented.** An intended-but-not-yet-real relationship gets `{ tags "Planned" }` and renders dashed via `views.dsl`. Never track a not-yet-real edge in a prose comment, where a stale claim goes unnoticed. `tach.toml` is what confirms a Planned edge: the tag is flipped when the dependency lands there, and the `architecture-docs` diagram check re-checks tagged edges against it. Exception: a relationship to a hypothetical external system has no in-repo module `tach.toml` could confirm, so those stay in `model.dsl`'s header comment.
- **Technology conventions in use**: `"Python"` for in-process calls, `"Filesystem (Parquet)"` / `"Filesystem (Parquet/JSON)"` for anything touching `workspaceStorage`, `"HTTP/API/Bulk files"` for upstream-registry fetches, `"Python package import"` for external consumers, `"CLI"` for a person driving a script, `"Jupyter Notebook"` for notebook interaction.
